# 数据契约（工作流 ↔ 网页 的接口）

> 这是**唯一约定**：工作流的导出节点必须产出符合本契约的内容；网页只认这一份格式。
> 两边任何一方改动，都要先改这份文档。

---

## 1. 产出物形态

工作流**最后一个节点**输出一段 **JavaScript 文件内容**，形如：

```js
window.__LEDGER__ = { /* 见下方结构 */ };
```

- 之所以是 `.js` 而不是 `.json`：这样双击打开 `index.html`（`file://`）也能读到数据，**不需要本地服务器**，演示最省事。
- 替换方式：整段复制 → 覆盖 `网页/data.js` → 刷新页面。

---

## 2. 结构

```js
window.__LEDGER__ = {
  "meta": {
    "projectName": "连小理 · 班费透明工作流",
    "className": "2026 级 XX 班",
    "term": "2026—2027 学年 第一学期",
    "updatedAt": "2026-09-29 15:04",
    "isSample": false,
    "notice": "本页只展示账目信息，不经手资金、不执行支付、不代收代付。明细不含任何个人信息。"
  },
  "summary": {
    "balance": 1436.50,
    "incomeTotal": 2600.00,
    "expenseTotal": 1163.50
  },
  "budget": {
    "total": 3000.00,
    "warnBelow": 200.00
  },
  "members": {
    "visible": true,
    "standard": 100.00,
    "list": [
      { "name": "王子航", "paid": 100.00, "status": "paid" },
      { "name": "谢文轩", "paid": 100.00, "status": "paid", "masked": true },
      { "name": "曹思彤", "paid": 50.00,  "status": "partial" },
      { "name": "沈书言", "paid": 0,      "status": "unpaid" }
    ]
  },
  "ledger": [
    {
      "id": "20260912-OUT-01",
      "date": "2026-09-12",
      "type": "out",
      "category": "团建活动费",
      "amount": 186.00,
      "receipt": "P-2026-0912-03",
      "note": "班级团建买零食"
    }
  ]
};
```

---

## 3. 字段规则

### meta

| 字段 | 必填 | 说明 |
|---|---|---|
| `className` | ✅ | 班级名，如「2026 级 XX 班」 |
| `term` | ✅ | 学期 |
| `updatedAt` | ✅ | 更新时间，`YYYY-MM-DD HH:mm` |
| `isSample` | ✅ | **是否示例数据**。用真实账目时必须为 `false`；示例/演示为 `true`（网页会显示醒目提示） |
| `notice` | ✅ | 边界声明原文 |
| `projectName` | — | 固定值即可 |

### budget —— 学期预算（可选）

| 字段 | 必填 | 说明 |
|---|---|---|
| `total` | — | 本学期**预算总额**。填 `0` 或不填 = 不设预算，前台会自动隐藏预算区块 |
| `warnBelow` | — | **低余额提醒阈值**。余额低于此值时，由连小理定时任务**私聊生活委员本人**（不在群内发布） |

> 前台据 `total` 展示"已用百分比 / 剩余"，据 `expenseTotal` 计算已用金额。
> `warnBelow` 前台不展示，只作为定时任务的判断依据。

### members —— 班费收缴明细（前台公示，供同学监督）

| 字段 | 必填 | 说明 |
|---|---|---|
| `visible` | ✅ | 是否在网页公示。用真实数据务必为 `true`（这是"同学可监督"的依据）；调试阶段可设 `false` 隐藏整块 |
| `standard` | ✅ | 本学期**每人应缴金额**（全班统一标准） |
| `list[].name` | ✅ | 姓名。**如需隐藏该同学姓名，设 `masked: true`**（网页显示为"不公示"），姓名仍需填写以便生活委员核对 |
| `list[].paid` | ✅ | 该同学**已缴金额**（数字） |
| `list[].status` | ✅ | `"paid"` 已缴清 ｜ `"partial"` 部分缴纳 ｜ `"unpaid"` 未缴。**网页会按 `paid` 与 `standard` 重算，不盲信此字段** |
| `list[].masked` | — | 为 `true` 时前台不显示姓名 |

**只放"班费收缴"这一项。** 个人在活动里吃了多少、买了什么，一律不进这里。

> 一致性：`members.list` 的 `paid` 合计应与 `ledger` 中收入条目合计相等（允许因记录时点不同有差异，但网页会在控制台提示核对）。

### ledger[] —— 账目条目（唯一真实来源）

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 条目编号，建议 `YYYYMMDD-类型-序号`，如 `20260912-OUT-01` |
| `date` | ✅ | `YYYY-MM-DD` |
| `type` | ✅ | `"in"` 收入 ｜ `"out"` 支出 ｜ `"adjust"` 更正 |
| `category` | ✅ | 类别名，**必须来自知识库口径** |
| `amount` | ✅ | 数字。`in` / `out` 用**正数**；`adjust` 用**带符号差值**（多记则负数） |
| `receipt` | ✅ | 票据编号，用于回溯（无票据时填 `"—"`） |
| `note` | ✅ | 备注，**不得含个人信息** |
| `corrects` | 仅 adjust | 被更正的条目 `id` |

### summary —— 仅供参考

网页会用 `ledger` **重算**收入 / 支出 / 余额；若与此处不一致，以明细重算为准，并在控制台给出提示。
**不要为了凑数去改 ledger。**

---

## 4. 硬性禁止

| 禁止 | 原因 |
|---|---|
| 在 `members` 里写**个人消费**信息（谁在活动里花了多少、买了什么） | 只公示"班费收缴"，不公示个人消费 |
| 出现学号、手机号、订单号、住址、头像 | 网页对全班公开 |
| 出现支付 / 收款 / 转账 / 代收代付类条目 | 本工具不经手资金 |
| `isSample: false` 但数据是编的 | 违反「不得虚构」 |

---

## 5. 自检清单（导出前逐条过）

- [ ] `ledger` 每条都有 `id` / `date` / `type` / `category` / `amount` / `receipt` / `note`
- [ ] 每个 `type` 与 `amount` 符号匹配（`in`、`out` 为正；`adjust` 带符号）
- [ ] 所有 `category` 都在知识库口径内，没有"其他杂项"这类随意命名
- [ ] `members.standard` 已填，且 `list` 覆盖**全班每一个人**（不能只列已缴的）
- [ ] `members` 里**没有**任何个人消费信息，只有收缴金额
- [ ] 需要隐藏姓名的同学已设 `masked: true`
- [ ] 除姓名外，全文搜索不到学号 / 手机号 / 订单号
- [ ] 更正条目都带 `corrects`，且指向真实存在的 `id`
- [ ] **概览与走势同口径**：按日期升序累加 `ledger`（`in` 取 `+amount`，`out` 与 `adjust` **一律取 `−amount`**），累加**末值必须等于 `summary.balance`**。
      更正条目是**带符号差值**，它修正的是支出，所以方向必须与被更正的支出一致 —— 这里取反一次就会让走势图与概览相差 `2 × 差值`。
- [ ] 每条更正的**净额**（原条目 `amount` + `adjust.amount`）不为负数；为负说明差值的正负或数值填反了
- [ ] `isSample` 取值与数据真实性强一致
- [ ] 与上一次导出相比，**只新增条目，没有改动历史条目**
