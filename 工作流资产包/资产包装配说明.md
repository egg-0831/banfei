# 工作流资产包 · 怎么用

> 这里是可以**直接拿去装配**的东西：一份知识库文档、一套节点提示词、一份数据契约。
> 装配地点：连小理客户端（SSO 域名 `dlut` 登录）。

---

| 文件 | 用途 | 装到哪 |
|---|---|---|
| `知识库-班级账务口径.md` | 分类与记账的判断依据 | 上传为**知识库** |

## 二、装配步骤

### 第 1 步 · 建工作空间
1. 登录连小理客户端
2. 新建工作空间，命名「**班费透明工作流**」
3. 在工作空间内新建工作流，命名「**班费透明工作流 · 主流程**」

### 第 2 步 · 挂知识库
1. 上传 `知识库-班级账务口径.md`
2. 知识库命名「**班级账务口径**」
3. 可见范围设为**班级内部可见**
4. 绑定给本工作流

### 第 3 步 · 按顺序加节点
打开 `节点提示词.md`，**逐节**把提示词粘进对应节点：

| 顺序 | 节点 | 关键要求 |
|---|---|---|
| ① | 触发 | 支持文字 / 语音 + 图片 |
| ② | 票据识别 | 只提取，不分类不计算；不确定要标出来 |
| ③ | 分类 | 挂上知识库；必须给判定依据；信息不足要回问 |
| ④ | 核算 | 列出算式；余额低于 `budget.warnBelow` 时提醒（阈值从数据读，不要写死数字） |
| ⑤ | 回显确认 | 只出卡片，**不写数据** |
| ⑥ | 写账 | 仅「确认」后执行；只追加不改历史 |
| ⑦ | 生成公示 | 严格脱敏；姓名不进公示文案 |
| ⑧ | 导出 | 输出整段 `window.__LEDGER__ = {...};`，**含 `members` 收缴明细** |

### 第 3.5 步 · 加一个「个人明细查询」节点
在 `节点提示词.md` 第 ⑩ 节：生活委员可在工作流里查某人缴了多少、谁是未缴清。
**注意**：此节点只展示给生活委员本人，**不要生成发到班级群的点名文案**。

### 第 4 步 · 设定时任务
1. 新建定时任务，命名「**每日余额检查**」
2. 频率：**每日一次**（建议傍晚）
3. 粘贴 `节点提示词.md` 第 ⑨ 节的提示词
4. 确认：提醒只发**生活委员本人**，不进群

### 第 5 步 · 试跑（这一步不能省）
1. 用**测试金额**（比如 10 元）走一遍 ①→⑧
2. 检查导出内容是否符合 `数据契约.md`：字段齐不齐、符号对不对
3. 检查收入条目的 `category` 是否只有 `班费收缴` / `其他收入`，没有自造类别或自造 `type`
4. 通过后，把 `网页/data.js` 换成导出内容，刷新网页看是否正常
5. **把每一步截图存档**（"可行性"维度的证据 + 录屏素材）

## 三、装配自检清单

- [ ] 知识库已上传并绑定到本工作流
- [ ] 8 个节点按 ①→⑧ 顺序连通
- [ ] 每个节点都粘贴了对应提示词，没有共用一段

- [ ] 定时任务只私聊本人，没有生成发群文案
- [ ] 试跑通过，导出内容能被网页正确读取
- [ ] 全过程截图已存档

## 四、最容易踩的三个坑

| 坑 | 表现 | 怎么避免 |
|---|---|---|
| 导出节点夹带解释 | 输出里出现"好的，以下是…" | 提示词里已明确"只输出这一整段，不要有任何解释文字"；试跑时必须检查首字符是不是 `window.__LEDGER__` |
| 汇总与明细对不上 | 网页余额和台账不符 | 网页已改为**由明细重算**；工作流的 `summary` 只作参考，别为了凑数改明细 |
| 分类漂移 | 同一类支出今天叫"团建"明天叫"活动" | 「分类」节点必须挂知识库，且要求输出判定依据 |
