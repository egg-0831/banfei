# 连小理 · 班费透明工作流

> 让每一笔班费都看得见 —— 从一张票据，到全班可逐笔核对的公开账册。

班费的问题不在钱多钱少，而在**看不见**：收了多少、花了哪、还剩多少，通常只活在生活委员的手机相册和几张群聊截图里。
这个项目把它变成**一份可核对的公开账册**：生活委员把票据丢进连小理，工作流识别、按口径归类、核算余额，生成全班只读的公示页。

![前台](截图/前台-桌面.png)

## 它能做什么

- **票据识别**：读票据/支付截图，只提取金额、日期、商户、支付方式；看不清一律标"不确定"，不猜不编；票据上的人名、手机号、订单号**不提取、不复述**
- **按口径归类**：依知识库《班级账务口径》判类，只能落在四个类别内，且必须说明依据；信息不足时**回问用途**而不是猜
- **更正留痕**：记错不改历史 —— 另立一条 `adjust`，记**带符号差值**并指回原条目，页面用朱红「更正」戳记标出，可见完整更正链路
- **双向汇总**：页面所有数字都由逐笔明细**重算**，同时保留工作流汇总作对照；两者不符时直接说明"已采用明细重算值"并亮黄灯
- **收缴明细**：覆盖全班每个人（已缴清 / 部分 / 未缴），支持"不公示"（本人申请隐藏姓名则显示为"不公示"）
- **低余额提醒**：低于提醒线时**只私聊生活委员本人**，不群内点名、不生成催缴文案
- **问一问账目**：页面内离线规则引擎只用手上的数字作答；算不出来时明确说不猜，引导换个问法
- **发布前校验**：后台 13 项校验（字段完整性、金额正负、类别是否在口径内、`adjust` 的 `corrects` 是否指向真实条目、汇总口径是否与明细一致…），不通过不允许发布

## 快速开始

### ① 只看页面（最省事）

双击 `网页/index.html`。**不需要服务器、不需要联网** —— 数据写在 `网页/data.js` 里，浏览器直接读。

> 仓库里的 `网页/data.js` 是**虚构的示例数据**（页面三处标注"示例数据 · 非真实班费"）。
> 真实使用时，把 `网页/data-空壳模板.js` 复制为 `data.js`，从空白账本开始录。

### ② 看后台录入（本地服务）

```bash
cd server
node server.js
# 首次启动会打印一个随机管理口令（本项目不内置默认密码）
```

- 公示页：<http://localhost:3300>
- 后台：<http://localhost:3300/admin>（输入启动时打印的口令）

服务端只用 Node 内置模块，**不需要 `npm install`**。要接在线问答，把 `server/.env.example` 复制为 `.env` 并填入你自己的 `DEEPSEEK_API_KEY`。

### ③ 公网静态托管

把 `网页/` 目录（含 `data.js`）整个上传到任意静态托管即可，无需 Node。

## 目录结构

```
网页/            全班只读公示页（index.html / style.css / app.js / data.js）
后台/            生活委员操作台（录入 · 更正 · 收缴 · 预算 · 校验 · 发布）
server/          本地小后端（静态托管 + store.json + 模型代理；无 npm 依赖）
工作流资产包/     连小理侧的节点提示词、数据契约、账务口径、装配说明
文档/            方案文档、技术栈说明（PDF）
截图/            页面实拍
```

## 数据口径（改数据前必读）

单一数据源是 `网页/data.js`，导出 `window.__LEDGER__`，五个顶层字段：`meta / summary / budget / members / ledger`。

```
支出 = Σ|out| + Σ(adjust 带符号值)
余额 = 收入 − 支出
```

因此 **`adjust` 负数 = 支出减少（余额增加），正数 = 支出增加**。
写完数据请打开页面看「一致性提示」—— 不一致时它会亮黄灯并采用明细重算值。

条目编号规则：`YYYYMMDD-类型-序号`（类型取 `IN` / `OUT` / `ADJ`）；每条 `adjust` 必须带 `corrects` 指向真实存在的条目。

## 四条边界

1. **不经手资金**：不支付、不收款、不代收代付。只做账，不碰钱。
2. **姓名只出现在一处**：只在「班费收缴明细」区；账目备注不含姓名。学号、手机号、订单号、邮箱一律不采集。
3. **不公示个人消费**：除班费收缴外不展示任何个人消费信息；不生成群内点名催缴的文案。
4. **数据不出域**：真实班级数据不上传公网。需要公网演示时**只使用虚构示例数据**。

> 仓库里的示例数据全部为虚构（班号、姓名、金额、票据编号均为演示而编），不代表任何真实班级。

## 技术要点

- **零依赖、零构建**：原生 HTML/CSS/JS；图表全部手写 SVG；服务端仅用 Node 内置模块
- **可离线**：数据写在本地文件里，双击即用
- **只动 `transform` / `opacity`**：条形生长用 `scaleX`，不用 `width` 过渡，避免触发布局重排
- **台账只增不改**：后台刻意没有删除按钮

更完整的技术栈、运行方式、实现决策与已知限制见 [`文档/技术栈说明.pdf`](文档/技术栈说明.pdf)。

## 已知限制

- 单机、单用户：没有多用户权限体系，后台只有一个管理口令
- 无云端数据库：数据是单个 `store.json`，不做多设备实时同步
- 无独立审计日志：靠"只增不改 + 更正条目"间接体现
- 票据识别依赖模型能力：模糊/遮挡的票据会落到"不确定"，要求重拍或手填，而不是猜
